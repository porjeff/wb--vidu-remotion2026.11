# 多代理并行建镜（模板档）

长片（40 秒以上、镜头 >12）用这个方式：主会话写导演表，把镜头切成组，派多个代理各写一组，主会话合并 + 自检。解决单线写镜导致的"镜头过长、切点太少、节奏偏慢"。

借鉴 anything2explainer（3.4k 星）的多代理分工协议，代码不共用，只用方法。那套工具是 PolyForm 非商用协议——**只借鉴思路，不搬代码**。

## 什么时候用

| 片长 | 镜头数 | 做法 |
|---|---|---|
| < 40 秒 / < 12 镜 | 少量 | 主会话直接写完整 film.js，不必并行 |
| 40–90 秒 / 12–25 镜 | 中等 | 切 3–4 组，每组 4–6 镜 |
| > 90 秒 / > 25 镜 | 长 | 切 5–8 组，每组 5–7 镜；先做第一组样片给用户定风格 |

## 分组原则

1. **按场景/章节切，不平均切**：一组是一个完整的叙事单元（钩子组、立事实组、拆数字组、收尾组）。同组镜头共享素材和主角，代理容易保持承接。
2. **组边界要有承接**：上一组最后一镜留下什么（数字/人/原文），下一组第一镜要接住。在导演表里把边界那一列写清，派单时明确告诉两个代理。
3. **第一组是风格样片**：G1 写完先渲 30 秒（或 G1 全部）给用户确认。风格、字号、语速在这里改一次只花一组成本；全片渲完再改要重做所有组。
4. **每组 5–7 镜**，不超过 7——多了代理容易虎头蛇尾。

## 派单（给每个代理的 prompt 模板）

```
你在做一条 wallstreet-explainer 财经解读片的第 G{n} 组镜头。
只写这一组，不要碰别的文件。

必读（按顺序）：
1. <skill>/SKILL.md 的"五条硬规矩"和"模板档：一条片怎么做"
2. <skill>/references/rules.md 全文（带编号的硬规则 + 场景决策表）
3. <skill>/kit/README.md 里你用到的场景的参数和例子
4. 本片 <film>/导演表.md（全片计划，你只负责其中 G{n} 行）
5. <film>/G1样片/film.js（已验收的风格样例，照它的写法和密度）

输出：
- <film>/shots/G{n}.js，格式是一个镜头数组的片段：
  // G{n} 第 x–y 镜
  {scene:'...', until:'@b..', says:'...', ...},
  ...
  只写数组元素（含逗号），不要写 window.ready 或 K.film 包装。

硬要求：
- 每镜写 says，一镜一个主角，场景从决策表里选对得上的行
- 时刻写 '@句id:词'，词照 script.json 一字不差
- 真素材镜头占比 ≥ 本组镜头数 × 0.4，占位图一张不留
- 同场景不连用三次；40 秒以上片全片至少 4 种场景（组间由主会话协调）
- 长镜头拆开：单镜尽量 ≤ 5 秒，超过 6 秒要在这一镜里加落点（steps/at/flip 等）

写完自己检查：
- 每个 until 的词在 script.json 对应句里真实存在
- 引用的图片/帧序列文件真实存在
- 不写注释以外的解释，交付就是那个 .js 片段文件
```

## 主会话合并

各组完成后，主会话按顺序拼接 `shots/G1.js … Gn.js` 到 `film.js` 的 `K.film([...])` 里：

```
await K.film([
 <G1 内容>
 <G2 内容>
 ...
]);
```

合并后必做：
1. `node scripts/render.mjs --dir <film> --check` —— 零报错才算过
2. 逐条处理"要看一眼"：长镜头拆开、占位图换真素材、接法重复改掉
3. `--sheet` 看每镜三帧，重点看**组边界**那两镜承接是否自然
4. 全片渲完跑 `frame_metrics.py`（量化 QC）和 `motion_check.py`（节奏）

## 节奏目标（解决切点太少）

我们第一条片实测：切点 14.4 次/分、一镜均长 6.5 秒，低于参考片（25–32 次/分、2.4–3.0 秒）。并行建镜时把下面写进派单硬要求：

- 单镜 ≤ 5 秒为目标，超过 6 秒必须有落点（节点 at、step、flip、cards、zoom 等）
- 一个 `says` 覆盖多句时，考虑拆成两镜各自说一件事
- 真素材镜头之间不要连续硬切超过两次，中间插一个图形镜承接
- 收尾的 `statement` 金句镜可以长（留给用户读完），但不要超过 10 秒

## 并发控制

- 一组一个代理，同时最多 4 组（受本机/harness 的 agent 上限约束）
- 每组只写自己的 `shots/G{n}.js`，绝不改共享文件（script.json / film.js / 素材目录）——这是避免冲突的关键
- 代理之间不直接通信，全部通过主会话传递组边界的承接信息
